# 5분 해커톤 시연 가이드

목표는 새 사용자가 가입하고 영양제를 등록한 뒤, 완료 기록과 성분 중복을 확인하는 실제 흐름을 보여주는 것입니다. 표와 카드에 보이는 값이 입력·저장·조회로 만들어진다는 점을 강조합니다.

## 발표 전 준비

1. README대로 설치하고 `.env`를 복사합니다. 현장에서 외부 메일 서비스에 의존하지 않을 경우 `EMAIL_MODE=capture`를 사용합니다.
2. `pnpm dev`를 실행하고 [http://localhost:3000](http://localhost:3000)을 엽니다.
3. `CRON_SECRET`을 설정한 경우 두 번째 터미널에서 `pnpm reminders`를 실행합니다.
4. 시연용 이메일·비밀번호를 정합니다. 비밀번호는 10자 이상이며 실제 사용 중인 비밀번호를 재사용하지 않습니다.
5. 알림 시연에 실제 이메일이 필요하면 사전에 Resend 키·도메인·수신 주소를 확인하고 받은편지함 도착까지 테스트합니다. 캡처 내역을 실제 전송이라고 소개하지 않습니다.
6. 모바일 브라우저 또는 개발자 도구에서 화면 폭 약 390px으로 대시보드와 영양제 등록 화면을 미리 확인합니다.

외부 발송 없는 시연에서는 `demo@example.com` 같은 발표용 주소로 회원가입할 수 있습니다. 실제 이메일 모드에서는 본인이 접근 가능한 이메일을 사용합니다.

## 0:00–0:40 · 서비스 소개와 회원가입

“하루영양은 어떤 성분을 더 먹으라고 처방하는 서비스가 아니라, 내가 등록한 영양제와 복용 체크를 관리하는 서비스입니다.”

랜딩 → 회원가입에서 이름·만 나이·이메일·비밀번호를 입력합니다. 아래 UL 시연은 만 30세 계정을 기준으로 합니다. 첫 시작 화면에서 **“이미 먹고 있는 영양제가 있어요”**를 선택합니다. 로그인 상태와 사용자 이름을 보여줍니다.

## 0:40–1:50 · 영양제 두 개 등록

| 제품       | 하루 횟수 | 시간 예시 | 하루 성분 함량                           |
| ---------- | --------- | --------- | ---------------------------------------- |
| 종합비타민 | 1회       | 09:00     | 비타민 C 100mg, 비타민 D 20μg, 아연 10mg |
| 비타민D    | 1회       | 20:00     | 비타민 D 25μg                            |

제조사는 비워 두거나 “시연 제품”이라고 입력합니다. “성분 추가”로 한 제품에 여러 행을 넣고 저장합니다. 함량은 **하루 총량**이며, 제품을 하루 두 번 먹더라도 횟수를 다시 곱하지 않는다는 안내를 짚습니다.

입력 시간을 줄이려면 빈 대시보드의 “예시 성분을 확인하고 등록하기”를 사용합니다. `/supplements/new?example=multivitamin`으로 이동해 종합비타민 초안을 채우며 **자동 저장하지 않습니다**. 초안을 확인·수정하고 “성분 검사”를 누른 뒤, 경고가 있으면 내용을 확인하고 저장합니다. 나이에 따라 예시 함량에도 경고가 나타날 수 있으며 같은 검사 절차를 거칩니다.

제품 이름은 라벨을 식별하는 용도이고 특정 브랜드의 효능·안전성을 추천하는 것이 아닙니다.

## 1:50–2:20 · 중복 검사

성분 중복 화면을 엽니다. 비타민 D가 두 제품에 포함되고 각 20μg·25μg, 총 45μg으로 표시되는지 보여줍니다.

“동일한 성분이 두 제품에 있다는 사실을 표시합니다. 이 수치만으로 과다·위험 여부를 판단하지 않습니다. 식사나 등록하지 않은 제품은 합계에 들어 있지 않습니다.”

추가 설명이 필요하면 0.02mg와 20μg는 같은 질량 단위로 환산할 수 있고, UL 비교에서는 비타민 D에 한해서 40IU=1μg의 공식 환산을 지원한다고 설명합니다. 다른 성분 IU는 임의로 질량과 합치지 않습니다.

### 확장 시연 · 상한량 경고와 삭제 (추가 1분)

1. 새 제품에 비타민 D 80μg을 입력하고 저장 전 미리보기를 확인합니다.
2. 기존 45μg + 추가 80μg = 125μg, 만 30세에 적용한 공식 UL 100μg, 출처 링크를 보여줍니다. “추가로 먹으라는 권장량이 아니라 등록된 합계에 대한 참고 비교”라고 설명합니다.
3. 경고 확인 전에는 저장을 마치지 못하며, 확인 후 저장할 수 있음을 보여줍니다. 실제 복용을 권하지 않습니다.
4. 이 시연 제품을 삭제합니다. 오늘의 일정과 진행률, 제품 목록, 성분 분석에서 빠지는지 확인합니다. 복용 완료 후 삭제한 제품도 오늘의 목록에는 남지 않고 기록 화면에만 보관됩니다.
5. 로그아웃·재로그인 후 삭제 상태가 유지되는지 확인합니다.

연령이 없는 기존 계정은 설정에서 나이를 입력하기 전 “나이 입력 필요”로 표시합니다. 지원하지 않는 성분이나 적용 형태가 불명확한 항목이 “안전”으로 표시되지 않는지도 보여줄 수 있습니다.

## 2:20–3:00 · 복용 체크와 저장 확인

대시보드에서 “복용 완료”를 누릅니다. 오늘 2건 중 1건을 체크하면 50%가 됩니다. 완료 시각을 확인하고 새로고침해 상태가 유지되는지 보여줍니다. 다시 누르는 취소 동작도 확인할 수 있습니다.

기록 화면을 열어 오늘의 완료·미확인 상태가 연결되는지 보여줍니다. 새 계정에는 실제 과거 데이터가 없으므로 지난 7일을 임의의 100% 기록으로 채우지 않습니다. 연속 기록은 실제 저장된 완료 기록으로 계산합니다.

## 3:00–3:35 · 사용자 데이터 분리

로그아웃 후 다른 시연 계정으로 가입합니다. 다른 계정의 영양제와 복용 기록이 나타나지 않는지 확인합니다. 기존 계정으로 다시 로그인하면 앞서 저장한 항목이 보입니다.

시간이 부족하면 이 동작은 발표 전 검증하고 “서버가 로그인 사용자를 기준으로 데이터 소유권을 검사합니다”라고 설명합니다.

## 3:35–4:10 · 생활습관 설문

설문에서 햇빛·식사·채소와 과일·생선·피로·운동·수면에 답합니다. 결과 화면에서 “관심 있게 확인해볼 영양성분”과 참고 자료를 확인합니다.

“이 결과는 규칙 기반의 정보 안내입니다. 영양소 부족 여부를 판단하지 않고, 제품을 반드시 추가하도록 요구하지 않습니다.”

결과에서 영양제 등록으로 이어지는 버튼을 보여줍니다.

## 4:10–5:00 · 본인·보호자 알림

설정에서 본인 이메일 알림과 유예 시간을 확인합니다. 보호자 화면에서 이메일을 입력하고 동의 체크박스를 저장합니다. 본인 알림 후에도 추가 유예 시간 동안 완료가 확인되지 않는 경우에만 보호자에게 안내한다는 순서를 설명합니다.

### 캡처 모드

알림 내역 화면에서 현재 모드와 메시지 내용을 보여줍니다. UI에 있는 시연/확인 동작은 해당 계정 범위에서 사용합니다. 반드시 “실제 발송 대신 동일한 알림 내용을 DB에 캡처한 화면”이라고 설명합니다. 동의 없는 보호자 수신자나 다른 사용자의 데이터로 시연하지 않습니다.

시연/확인 버튼도 현재 시간의 알림 조건을 그대로 검사합니다. 시간이 아직 지나지 않았다면 메시지를 억지로 생성하지 않습니다. `resend` 모드에서 누르면 조건을 만족한 본인·보호자에게 실제 발송될 수 있습니다.

예약 실행 자체를 검증하려면 미완료인 일정과 설정한 유예 시간이 지나도록 준비하고 워커를 실행해 둡니다. 예정 시간만 지났다고 즉시 알림이 생기는 것은 아니며, 워커의 다음 실행까지 약 1분이 더 걸릴 수 있습니다. 보호자 알림은 본인 알림 이후 추가 유예 시간이 필요합니다.

### 실제 이메일 모드

앱 내 발송 상태뿐 아니라 Resend 대시보드와 실제 수신함을 확인합니다. 제목·본문에 “복용 완료가 아직 확인되지 않았습니다”가 표시되는지 보여줍니다. 외부 공급자 지연에 대비해 미리 확인한 캡처 모드 시연도 준비합니다.

현재 검증에서는 실제 메일 1통의 공급자 `Delivered` 상태까지 확인했습니다. 받은편지함에서 사용자가 직접 확인하는 단계는 미완료입니다. 발표 시에는 직접 확인한 단계까지만 설명합니다. 반복 시연으로 같은 수신자에게 여러 통을 보내지 않도록 평소 발표는 `capture` 모드를 사용합니다.

## 발표 후 직접 재현할 체크리스트

- [ ] 이름·나이를 포함한 새 계정 가입과 로그아웃·재로그인
- [ ] 여러 성분·복용 시간을 가진 제품 저장
- [ ] 브라우저 새로고침과 서버 재시작 후 저장 유지
- [ ] 복용 완료 시각 저장, 완료 취소, 진행률 변경
- [ ] 중복 성분의 제품별 함량과 총량
- [ ] 현재 등록량과 새 제품의 합산 미리보기, 수정 대상 제외
- [ ] 공식 출처·연령에 따른 UL 비교 및 초과 경고 확인
- [ ] 완료한 제품 삭제 후에도 오늘의 목록·진행률·분석에서 제외
- [ ] 기존 계정·기록 보존과 나이 미입력 안내
- [ ] 최근 기록과 등록 전 날짜의 처리
- [ ] 계정 간 조회·수정 권한 분리
- [ ] 본인 알림 생성과 중복 실행 시 반복 생성 방지
- [ ] 보호자 동의 전·후 및 동의 철회 동작
- [ ] 모바일에서 가로 스크롤·잘린 버튼 없이 주요 흐름 진행

과거 기록·실제 이메일 도착·배포 환경에서 확인하지 않은 항목은 검증했다고 발표하지 않습니다.
