# 5분 해커톤 시연 가이드

목표는 새 사용자가 가입하고 영양제를 등록한 뒤, 완료 기록과 성분 중복을 확인하는 실제 흐름을 보여주는 것입니다. 표와 카드에 보이는 값이 입력·저장·조회로 만들어진다는 점을 강조합니다.

제품 검색·관심 제품 정렬·비밀번호 재설정은 아래 추가 시연 순서로 연결합니다. 이번 추가 기능의 실제 공식 API와 운영 재설정 검증은 아직 완료 전입니다. 기존 복용 알림의 실측 결과를 새 인증메일 결과로 소개하지 않습니다. [현재 검증 범위](VERIFICATION.md)

## 발표 전 준비

1. README대로 설치하고 `.env`를 복사합니다. 현장에서 외부 메일 서비스에 의존하지 않을 경우 `EMAIL_MODE=capture`를 사용합니다.
2. `pnpm dev`를 실행하고 [http://localhost:3000](http://localhost:3000)을 엽니다.
3. `CRON_SECRET`을 설정한 경우 두 번째 터미널에서 `pnpm reminders`를 실행합니다.
4. 시연용 이메일·비밀번호를 정합니다. 비밀번호는 10자 이상이며 실제 사용 중인 비밀번호를 재사용하지 않습니다.
5. 실제 이메일 시연은 사전에 Brevo 계정·API Key·확인한 Sender를 설정하고 본인·별도 외부 수신자·동의한 보호자의 실제 도착까지 확인합니다. 캡처 내역을 실제 전송이라고 소개하지 않습니다.
6. 모바일 브라우저 또는 개발자 도구에서 화면 폭 약 390px으로 대시보드와 영양제 등록 화면을 미리 확인합니다.
7. 공식 검색은 `FOOD_SAFETY_API_KEY`와 I0030 활용 신청이 필요합니다. 키가 없는 환경에서는 직접 입력을 시연하고 가상 테스트 응답을 실제 제품 조회라고 소개하지 않습니다.
8. 비밀번호 재설정은 실제 `EMAIL_MODE=brevo`에서만 시연합니다. 발표용 계정의 메일 접근을 확인하고 코드·비밀번호 입력 중에는 화면 공유를 가립니다.

외부 발송 없는 시연에서는 `demo@example.com` 같은 발표용 주소로 회원가입할 수 있습니다. 실제 이메일 모드에서는 본인이 접근 가능한 이메일을 사용합니다.

## 0:00–0:40 · 서비스 소개와 회원가입

“하루영양은 어떤 성분을 더 먹으라고 처방하는 서비스가 아니라, 내가 등록한 영양제와 복용 체크를 관리하는 서비스입니다.”

랜딩 → 회원가입에서 이름·만 나이·이메일·비밀번호를 입력합니다. 아래 UL 시연은 만 30세 계정을 기준으로 합니다. 첫 시작 화면에서 **“이미 먹고 있는 영양제가 있어요”**를 선택합니다. 로그인 상태와 사용자 이름을 보여줍니다.

## 0:40–1:50 · 영양제 두 개 등록

| 제품       | 하루 횟수 | 시간 예시 | 하루 성분 함량                           |
| ---------- | --------- | --------- | ---------------------------------------- |
| 종합비타민 | 1회       | 09:00     | 비타민 C 100mg, 비타민 D 20μg, 아연 10mg |
| 비타민D    | 1회       | 20:00     | 비타민 D 25μg                            |

제조사는 비워 두거나 “시연 제품”이라고 입력합니다. “성분 추가”로 한 제품에 여러 행을 넣고 저장합니다. 함량은 **하루 총량**이며, 제품을 하루 두 번 먹더라도 횟수를 다시 곱하지 않는다는 안내를 짚습니다.

입력 시간을 줄이려면 빈 대시보드의 “예시 성분을 확인하고 등록하기”를 사용합니다. `/supplements/new?example=multivitamin`으로 이동해 종합비타민 초안을 채우며 **자동 저장하지 않습니다**. 초안을 확인·수정하고 “성분 검사”를 누른 뒤, 경고가 있으면 내용을 확인하고 저장합니다. 나이에 따라 예시 함량에도 경고가 나타날 수 있으며 같은 검사 절차를 거칩니다.

제품 이름은 라벨을 식별하는 용도이고 특정 브랜드의 효능·안전성을 추천하는 것이 아닙니다.

## 1:50–2:20 · 중복 검사

성분 중복 화면을 엽니다. 비타민 D가 두 제품에 포함되고 각 20μg·25μg, 총 45μg으로 표시되는지 보여줍니다.

“동일한 성분이 두 제품에 있다는 사실을 표시합니다. 이 수치만으로 과다·위험 여부를 판단하지 않습니다. 식사나 등록하지 않은 제품은 합계에 들어 있지 않습니다.”

추가 설명이 필요하면 0.02mg와 20μg는 같은 질량 단위로 환산할 수 있고, UL 비교에서는 비타민 D에 한해서 40IU=1μg의 공식 환산을 지원한다고 설명합니다. 다른 성분 IU는 임의로 질량과 합치지 않습니다.

### 확장 시연 · 상한량 경고와 삭제 (추가 1분)

1. 새 제품에 비타민 D 80μg을 입력하고 저장 전 미리보기를 확인합니다.
2. 기존 45μg + 추가 80μg = 125μg, 만 30세에 적용한 공식 UL 100μg, 출처 링크를 보여줍니다. “추가로 먹으라는 권장량이 아니라 등록된 합계에 대한 참고 비교”라고 설명합니다.
3. 경고 확인 전에는 저장을 마치지 못하며, 확인 후 저장할 수 있음을 보여줍니다. 실제 복용을 권하지 않습니다.
4. 이 시연 제품을 삭제합니다. 오늘의 일정과 진행률, 제품 목록, 성분 분석에서 빠지는지 확인합니다. 복용 완료 후 삭제한 제품도 오늘의 목록에는 남지 않고 기록 화면에만 보관됩니다.
5. 로그아웃·재로그인 후 삭제 상태가 유지되는지 확인합니다.

연령이 없는 기존 계정은 설정에서 나이를 입력하기 전 “나이 입력 필요”로 표시합니다. 지원하지 않는 성분이나 적용 형태가 불명확한 항목이 “안전”으로 표시되지 않는지도 보여줄 수 있습니다.

## 2:20–3:00 · 복용 체크와 저장 확인

대시보드에서 “복용 완료”를 누릅니다. 오늘 2건 중 1건을 체크하면 50%가 됩니다. 완료 시각을 확인하고 새로고침해 상태가 유지되는지 보여줍니다. 다시 누르는 취소 동작도 확인할 수 있습니다.

기록 화면을 열어 오늘의 완료·미확인 상태가 연결되는지 보여줍니다. 새 계정에는 실제 과거 데이터가 없으므로 지난 7일을 임의의 100% 기록으로 채우지 않습니다. 연속 기록은 실제 저장된 완료 기록으로 계산합니다.

## 3:00–3:35 · 사용자 데이터 분리

로그아웃 후 다른 시연 계정으로 가입합니다. 다른 계정의 영양제와 복용 기록이 나타나지 않는지 확인합니다. 기존 계정으로 다시 로그인하면 앞서 저장한 항목이 보입니다.

시간이 부족하면 이 동작은 발표 전 검증하고 “서버가 로그인 사용자를 기준으로 데이터 소유권을 검사합니다”라고 설명합니다.

## 3:35–4:10 · 생활습관 설문

설문에서 햇빛·식사·채소와 과일·생선·피로·운동·수면에 답합니다. 결과 화면에서 “관심 있게 확인해볼 영양성분”과 참고 자료를 확인합니다.

“이 결과는 규칙 기반의 정보 안내입니다. 영양소 부족 여부를 판단하지 않고, 제품을 반드시 추가하도록 요구하지 않습니다.”

결과에서 영양제 등록으로 이어지는 버튼을 보여줍니다.

## 4:10–5:00 · 본인·보호자 알림

설정에서 본인 이메일 알림과 유예 시간을 확인합니다. 보호자 화면에서 이메일을 입력하고 동의 체크박스를 저장합니다. 본인 알림 후에도 추가 유예 시간 동안 완료가 확인되지 않는 경우에만 보호자에게 안내한다는 순서를 설명합니다.

### 캡처 모드

알림 내역 화면에서 현재 모드와 메시지 내용을 보여줍니다. UI에 있는 시연/확인 동작은 해당 계정 범위에서 사용합니다. 반드시 “실제 발송 대신 동일한 알림 내용을 DB에 캡처한 화면”이라고 설명합니다. 동의 없는 보호자 수신자나 다른 사용자의 데이터로 시연하지 않습니다.

시연/확인 버튼도 현재 시간의 알림 조건을 그대로 검사합니다. 시간이 아직 지나지 않았다면 메시지를 억지로 생성하지 않습니다. `brevo` 모드에서 누르면 조건을 만족한 본인·보호자에게 실제 발송될 수 있습니다.

예약 실행 자체를 검증하려면 미완료인 일정과 설정한 유예 시간이 지나도록 준비하고 워커를 실행해 둡니다. 예정 시간만 지났다고 즉시 알림이 생기는 것은 아니며, 워커의 다음 실행까지 약 1분이 더 걸릴 수 있습니다. 보호자 알림은 본인 알림 이후 추가 유예 시간이 필요합니다.

### 실제 이메일 모드

`EMAIL_MODE=brevo`로 설정한 실제 서버에서 아래 순서로 점검합니다. 이번 Railway 자동 워커의 두 차례 검사에서 **본인 Gmail·별도 Gmail 일반 알림·동의한 Gmail 보호자 알림의 실제 수신을 확인했습니다.** 본인과 보호자 메일은 기본 받은편지함, 별도 Gmail 일반 메일의 폴더는 미확인입니다. 학교 이메일의 두 건은 `Delivered`만 확인되어 수신 성공 사례로 발표하지 않습니다. 총 6통 모두 직접 API 호출이나 캡처가 아닌 워커의 시간 조건으로 발송했고 API 접수·`Delivered`를 확인했습니다. 설정 방법은 [README](../README.md#6-이메일-알림-연결), 상세 범위는 [검증 기록](VERIFICATION.md)을 따릅니다.

1. **A — 본인:** 본인이 확인할 수 있는 앱 가입 이메일로 새 제품·미완료 일정을 준비하고 자동 워커를 기다립니다. 앱 알림의 API 접수 상태와 Brevo Transactional → Logs의 이벤트를 확인한 뒤 실제 메일을 엽니다.
2. **B — 외부 수신자:** 발송에 동의한 별도 Gmail·Naver·학교 이메일 등으로 새 앱 계정을 준비합니다. 해당 주소는 Brevo 계정과 무관한 일반 수신자여야 합니다. 새 일정으로 같은 과정을 반복하고 수신자가 직접 확인합니다.
3. **C — 보호자:** 보호자 이메일과 동의를 저장합니다. 본인 알림을 먼저 보낸 뒤 추가 유예 시간 동안 완료를 체크하지 않고 보호자에게 전달되는지 확인합니다. 본인 알림을 건너뛰거나 보호자 동의 없이 보내지 않습니다.
4. 각 메일의 제목·본문이 “복용 완료가 아직 확인되지 않았습니다”라고 표현하는지, 일정·공개 서비스 링크·실제 From이 정확한지 확인합니다. 이번 로그의 Gmail Sender는 `*.brevosend.com`으로 대체됐고 Reply-To는 원래 주소였습니다. 대체 도메인은 공식 문서 예시와 같다고 가정하지 않습니다.
5. 다음 주기에 같은 알림이 추가 발송되지 않는지 확인합니다. 완료 처리나 제품 삭제 후에는 새 알림 대상에서 빠지는지도 확인합니다.

`sent`는 API 접수, `Delivered`는 공급자의 수신 서버 전달, 실제 받은편지함 확인은 수신자의 별도 관찰입니다. Gmail에서 안 보이면 계정을 확인하고 `in:anywhere 하루영양`으로 검색합니다. 스팸·프로모션·받은편지함 중 어느 폴더인지 직접 본 경우에만 기록합니다. 화면 공유에서 API Key·개인 이메일·다른 메일은 가립니다. [Brevo 로그 안내](https://help.brevo.com/hc/en-us/articles/360021533839-Manage-your-transactional-logs-and-email-previews)

시연을 위해 유예 시간을 줄였다면 종료 후 본인 알림을 기본 **30분**으로 되돌리고 테스트 제품을 삭제합니다. 반복 발표용 캡처는 별도 로컬 환경에서 명시적으로 사용하며, Brevo 발송 오류가 발생한 운영 서버를 자동 캡처로 바꾸지 않습니다. 오류나 미확정 결과는 그대로 설명하고 공급자 로그부터 확인합니다.

## 추가 시연 · 공식 제품 검색과 관심 성분 탐색

1. 영양제 추가 → “제품 검색으로 추가”에서 실제 제품명을 입력합니다. 공식 결과의 제품명·제조사·신고번호를 확인하고 섭취방법·주의사항·기준규격 원문을 보여줍니다.
2. 자동 입력 가능한 값과 “직접 입력 필요”를 구분합니다. “API의 기준규격을 하루 함량으로 바로 쓰지 않고, 표시량과 하루 섭취분을 명확히 연결할 수 있을 때만 불러옵니다”라고 설명합니다.
3. 확인 후 편집기로 불러와 성분·하루 함량·복용 시간을 검토합니다. 기존 중복·UL 미리보기와 필요한 경고 확인을 거쳐 저장합니다. 검색 오류가 나면 직접 입력으로 계속할 수 있음을 보여줍니다.
4. 설문 결과 → “이 성분이 포함된 제품 찾아보기”로 이동합니다. 관심 일치도·현재 제품과 겹치는 성분·확인 상태·정렬 이유를 보여줍니다.
5. 일반·확인 필요·주의 필요 영역을 구분합니다. “일치도는 관심 항목과 겹치는 비율이며 안전 점수가 아닙니다. 현재 검색한 일부 후보만 비교하고 전체 제품 순위를 뜻하지 않습니다”라고 설명합니다.

B군 관심은 확인된 개별 B 성분을 연결하는 하나의 관심 그룹입니다. 전체 B군이 들어 있다고 말하지 않으며 성분 합산·UL은 각각 유지합니다. A나 B2 같은 항목이 확인 필요로 나오는 결과를 시연 편의를 위해 일반으로 바꾸지 않습니다. [공식 데이터·정렬 설명](PRODUCT_DATA.md)

## 추가 시연 · 이메일 비밀번호 재설정

1. 본인이 관리하는 테스트 계정에서 로그아웃하고 “비밀번호를 잊으셨나요?”를 누릅니다.
2. 가입 이메일을 입력합니다. 화면은 계정 존재나 전송 성공을 단정하지 않는 접수 안내입니다. 메일 도착을 기다리고 필요한 경우 공급자 로그를 별도로 확인합니다.
3. 실제 메일을 받은 사용자가 6자리 코드를 직접 입력합니다. 코드는 요청 시점부터 10분 동안 유효하고 5회 실패하면 무효화됩니다.
4. 인증 후 5분 안에 새 비밀번호와 확인값을 직접 입력합니다. 서버는 원래 비밀번호를 보여주지 않고 새 해시로 교체합니다.
5. 로그인 화면으로 돌아가 새 비밀번호로 로그인합니다. 테스트 계정의 구 비밀번호 실패와 기존 세션 무효화, 제품·복용 기록 보존도 확인합니다.

재전송에는 60초 대기와 이메일별 시간당 5회 제한이 있습니다. 캡처 모드에서는 인증코드를 생성해 공개하지 않으며 실제 발송 설정이 없으면 오류를 안내합니다. 202 접수와 실제 발송 실패를 혼동하지 않습니다. 개인 실사용 계정의 비밀번호는 사용자 본인이 직접 변경하고, 발표 중 코드·쿠키·비밀번호를 보여주지 않습니다.
