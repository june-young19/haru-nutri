# 공식 제품 데이터와 관심 성분 정렬

이 문서는 구현한 데이터 처리 범위입니다. 실제 운영 인증키로 조회·등록하는 검증과 가상 응답을 사용하는 자동 테스트는 [검증 기록](VERIFICATION.md)에 구분합니다. 제품 탐색은 복용 처방·의학적 안전 판정이 아닙니다.

## 데이터 출처와 설정

식약처 식품안전나라의 **I0030 건강기능식품 품목제조신고** OpenAPI를 사용합니다. 공식 문서의 제품명 `PRDLST_NM`, 신고번호 `PRDLST_REPORT_NO` 조건을 서버에서 조회하며 쇼핑몰·검색엔진을 수집하지 않습니다. 문서에는 인증키 발급과 해당 서비스 활용 신청이 각각 필요하다고 안내합니다. [I0030 공식 문서](https://www.foodsafetykorea.go.kr/api/openApiInfo.do?menu_no=661&svc_no=I0030)

1. 식품안전나라 데이터활용서비스에서 인증키를 신청하고 I0030 활용 신청 상태를 확인합니다.
2. 발급된 값을 로컬 `.env` 또는 Railway 웹의 비밀 변수 `FOOD_SAFETY_API_KEY`에 넣습니다. 예제 파일에는 빈 자리만 남깁니다.
3. 웹 서버를 재시작하고 로그인한 뒤 제품명으로 검색합니다. 키가 없는 검색은 설정 오류를 안내하며 가짜 제품 결과를 표시하지 않습니다.

요청 대상은 `https://openapi.foodsafetykorea.go.kr`입니다. 이 API는 인증키를 요청 경로에 포함하므로 완성된 요청 URL을 로그·브라우저·공개 문서에 노출하지 않습니다. 사용자에게 제공하는 출처 링크는 인증키 없는 공식 문서입니다. 워커에 제품 API Key를 전달할 필요는 없습니다.

| 공식 필드                                  | 앱에서 사용하는 정보           |
| ------------------------------------------ | ------------------------------ |
| `PRDLST_NM`, `BSSH_NM`, `PRDLST_REPORT_NO` | 제품명·제조사·신고번호         |
| `NTK_MTHD`                                 | 섭취방법·하루 섭취분 판단 근거 |
| `PRIMARY_FNCLTY`, `IFTKN_ATNT_MATR_CN`     | 기능성·주의사항 원문           |
| `RAWMTRL_NM`, `STDR_STND`                  | 기능지표 성분·기준규격         |
| `PRODUCTION`, `LAST_UPDT_DTM`              | 생산 종료·수정일               |

제공되지 않는 정보는 “정보 없음” 또는 “직접 입력 필요”로 표시합니다. 일반·처방 의약품까지 같은 API로 검색한다고 안내하지 않습니다. 일반 제품명 조회에서 생산 종료 표시를 확인할 수 있으며, 관심 성분 후보 정렬에서는 종료 제품을 제외합니다.

## 하루 함량을 자동 입력하는 조건

공식 `STDR_STND`는 완성된 하루 영양성분 표가 아닌 **기준규격 텍스트**입니다. 이 프로젝트의 파서는 다음 조건을 모두 확인할 때만 `ingredients`에 하루 함량을 넣습니다.

- 구분 가능한 성분명과 하나의 명시적인 `표시량(함량/기준량)`이 있어야 합니다.
- 기준량이 하루 섭취량이거나, 섭취방법의 명확한 하루 질량과 환산할 수 있어야 합니다.
- 단위는 지원하는 질량 단위·IU의 정확한 수치여야 합니다. 모호한 범위나 여러 대안을 임의로 선택하지 않습니다.
- 같은 성분에 여러 표시량이 있으면 하나를 골라 쓰거나 더하지 않고 자동 입력에서 제외합니다.

가상의 텍스트 예에서 `표시량(100mg/1000mg)`과 명확한 하루 섭취량 `2000mg`을 함께 확인하면 하루 함량은 `200mg`입니다. 이는 파서 설명용 값이며 실제 제품·복용 권고가 아닙니다. 허용 오차 비율, 납·미생물 같은 검사 규격, 원료 투입량을 영양소 하루 함량으로 바꾸지 않습니다. RAE·DFE·NE 등 별도 당량을 일반 mg·μg로 환산하지 않습니다.

성분 이름이 확인됐으나 함량을 변환할 수 없으면 `declaredNutrients`에만 남겨 관심 일치는 계산할 수 있지만 수치 UL을 비교하지 않습니다. `parseStatus`는 `complete`·`partial`·`unavailable`로 구분합니다. `complete`는 파서의 입력 조건이 충족됐다는 뜻이며 제품 전체 정보·안전성을 보증하지 않습니다.

사용자가 선택한 제품은 편집기 **초안**으로 불러옵니다. 제품명·성분·하루 함량을 검토·수정하고 복용 시간을 직접 정한 뒤 기존 중복·UL 검사를 거쳐 저장합니다. 검색 결과 선택만으로 DB에 자동 등록하지 않으며 기존 직접 입력을 계속 사용할 수 있습니다. 원문은 [제품 파서](../lib/products.ts), 네트워크 처리는 [서버 어댑터](../lib/server/products.ts)에 있습니다.

## 검색 범위·캐시·한도

공식 문서의 증분 파라미터 없는 조회 한도는 시간당 100회입니다. 앱은 여유를 두고 같은 인증키의 외부 요청을 **시간당 80회**로 제한하며 이 예산은 SQLite에 저장되어 웹 재시작으로 초기화되지 않습니다. [I0030 호출 제한](https://www.foodsafetykorea.go.kr/api/openApiInfo.do?menu_no=661&svc_no=I0030)

응답은 웹 프로세스 안에서 1시간 캐시하고 같은 동시 요청을 합칩니다. 캐시는 최대 32개·12MB, 요청 응답은 최대 3MB·10초로 제한합니다. 일반 제품 검색은 페이지당 최대 100건이며 API 장애·한도 초과는 직접 입력 안내로 처리합니다. DB의 기존 사용자 데이터는 제품 API 장애와 무관하게 유지됩니다.

관심 성분 탐색은 성분명에서 최대 4개 **제품명 검색어**를 만들고 각 첫 페이지의 최대 100건을 조회합니다. 예를 들어 B군은 제품명 “비타민”으로 후보를 가져온 뒤 실제 표시된 개별 성분을 확인합니다. 여러 결과를 신고번호로 합치며 일부 요청이 실패하면 부분 결과임을 표시합니다.

이 기능은 **최대 400개의 원본 검색 행에서 추린 후보 비교**입니다. 원료·성분에 대한 서버 전체 검색, 모든 국내 제품의 순위, 시장 전체의 최적 제품을 의미하지 않습니다. 검색어·앞 페이지 범위 밖 제품은 빠질 수 있습니다.

## 확인 상태와 정렬

현재 활성 제품과 후보를 기존 `analyzeSafety`로 합산합니다. 후보에 없는 기존 성분의 불확실성이나 초과도 보수적으로 반영하고 이유에 “기존 등록분”이라고 구분합니다. 알려진 함량의 부분 합계만으로 이미 초과하는 경우에도 주의 필요로 분리하되 완전한 총량이라고 표시하지 않습니다.

| 그룹      | 판정                                                                   |
| --------- | ---------------------------------------------------------------------- |
| 일반 후보 | 검토 가능한 등록 정보에서 수치 UL 초과·미확인 항목이 발견되지 않음     |
| 확인 필요 | UL 미설정·형태·단위·나이·함량·원문 정보 부족 등으로 자동 확인이 불완전 |
| 주의 필요 | 기존 등록분과 후보 합산에서 확인한 참고 UL 초과가 있음                 |

“일반”은 안전 보장·복용 필요성의 의미가 아닙니다. “주의 필요”는 위험 제품이라는 단정이 아니며 별도 영역에서 확인합니다. 각 그룹 내 정렬은 아래 우선순위를 하나씩 비교합니다. 낮은 순위의 가산점으로 높은 우선순위를 뒤집지 않습니다.

1. 관심 성분 일치 수가 많음
2. 기존 제품과 겹치는 고유 성분 수가 적음
3. 후보 성분 중 수치 UL 분석이 가능한 비율이 높음
4. 하루 섭취 횟수가 적음. 횟수 미확인은 뒤에 배치
5. 제공된 메타데이터·성분량의 완전도가 높음
6. 동일한 조건에서는 안정적인 제품 ID 순서

일치도는 `일치한 관심 항목 / 고유 관심 항목 × 100`이며 0~100%입니다. 안전 점수나 복용 추천 점수로 쓰지 않습니다. B군 관심은 확인한 B1/B2/B3/B5/B6/B7/B9/B12 중 하나 이상이 있으면 **그룹 한 항목**으로 일치시킵니다. 어떤 개별 B 성분인지 이유에 표시하며 전체 B군이 포함됐다는 뜻이 아닙니다. 합산·중복·UL에서는 각 B 성분을 합치지 않습니다.

가상 자동 테스트는 수치 UL이 있는 성분으로 A>B>C 및 D의 주의 분리를 검증합니다. B의 추가 중복 두 개는 관심 성분 밖 기존 성분으로 구성해 논리적 모순을 피합니다. 실제 A·B2·D·마그네슘 예시는 A의 형태와 B2의 수치 UL 비교 한계를 그대로 남겨 “확인 필요”임을 별도 검사합니다. [정렬 코드](../lib/product-ranking.ts), [테스트](../tests/product-ranking.test.ts)
